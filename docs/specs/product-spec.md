# SemTrack 產品 Spec（MVP）

> 狀態：草案 v1 · 2026-11-17 · 對應原型：`semtrack-prototype.html`

## 1. 問題陳述

大學生跟不上課程 deadline。現有資訊散落在 Moodle、電郵、群組訊息與紙本 syllabus，學生缺乏**單一平台**掌握「這學期我還欠什麼、進行到哪裡」。

延伸痛點（Phase 2 處理）：
- 課件要一個一個手動下載，繁瑣；
- 檔案管理混亂：同一份 PDF 可能被重複下載多次、命名不一致、找不到最新版；
- Deadline 資訊埋在幾十頁 slides 裡，人工整理成本高。

## 2. 目標用戶

大學生（一學期修 3–6 門課），同時有個人作業與小組專題。桌面為主、手機查閱。

## 3. MVP 範圍（先落地，輕量）

**核心兩條主線：**

1. **Assignment 進度**
   - 資料庫式清單：名稱 / 課程 / 類型（作業、小測、考試）/ 截止日 / 狀態；
   - 狀態由截止日推導：已完成、未完成、剩 N 天（≤3 天警示）、已逾期；
   - 勾選即完成，可還原；課程與狀態篩選、空結果可一鍵清除；
   - 手動新增（名稱與日期必填、即時驗證、失敗保留輸入）。

2. **Group Project 進度**
   - 專題卡片：課程、成員、繳交日、進度條；
   - 詳情頁：任務清單（負責人、截止日、勾選完成）、里程碑、可新增任務；
   - **進度 = 已完成任務 / 全部任務**，即時推導並同步到總覽與日曆。

**輔助視圖：**
- 總覽：逾期數、7 天內到期數、完成比、即將到期隊列、各專題進度；
- 日曆（月視圖）：作業截止 + 專題里程碑 / 繳交日，點事件可標記完成或跳轉專題。

**MVP 資料輸入：** 手動建立。刻意不做自動匯入，先驗證「集中追蹤」本身的價值。

## 4. 非目標（MVP 不做）

- Moodle Extension 自動抓取與課件管理（Phase 2，見 §6）；
- LLM 從 slides 抽取 deadline（Phase 2）；
- 多人即時協作（MVP 為單人視角＋成員標記；組員各自勾選的共享機制列開放問題）；
- 通知 / 提醒推送、帳號付费功能、成績預測、番茄鐘等生產力周邊。

## 5. 驗收標準

- [ ] 新增 assignment：必填驗證、失败保留輸入、成功後清單 / 總覽計數 / 日曆同步出現；
- [ ] 勾選完成：總覽「已逾期 / 完成比」與日曆事件樣式即時聯動，可還原；
- [ ] 專題任務勾選 / 新增：詳情進度 %、總覽進度條、卡片计数一致（同一資料模型推導）；
- [ ] 篩選無結果時顯示空狀態並可清除恢復；
- [ ] 390px 與 1280px 均可用：導覽轉橫向、日曆可橫滑、無頁面溢出；
- [ ] 所有計數由同一 state 推導，無寫死的靜態數字。

（以上已在原型離線 QA 逐項驗證通過。）

## 6. Phase 2 路線：Moodle Extension ＋ 自動歸納

解決「逐個下載繁瑣＋重複下載＋檔案散亂」：

1. **瀏覽器 Extension**（Chrome/Edge MV3）在使用者既有 Moodle 登入態下，掃描課程頁資源列表，收集 PDF/slides 連結與中繼資料；
2. **去重與檔案索引**：以 content hash（SHA-256）去重，同一檔案多次出現只存一份；Web 端提供集中課件索引（課程 → 週次 → 檔案 → 版本），取代資料夾式管理；
3. **後端解析＋LLM 抽取**：PDF 轉文字 → LLM 抽取 deadline/考試（含信心分數與原文引用）；
4. **人工確認 queue**：抽取結果一律經學生核對（可改標題/日期/類型）才寫入日曆——LLM 不可靠時有兜底；
5. 相對日期（「下週五」「十二月初」）以學期起始日與課表解析，低信心標記推測。

## 7. 風險與開放問題

| # | 風險 / 問題 | 緩解 |
|---|---|---|
| R1 | 手動輸入摩擦大，學生懶得建檔 → 留存失敗 | MVP 表單極簡；Phase 2 自動匯入是留存關鍵 |
| R2 | 各校 Moodle DOM / 版本差異大 | Extension 用 per-site adapter，先支援 1–2 所目標學校 |
| R3 | LLM 日期抽取錯誤 | 人工確認 queue + 信心分數 + 原文引用 |
| R4 | 抓取涉及登入態與隱私 | 只讀使用者已登入課程、最小化收集、明確授權、不存帳密 |
| Q1 | Group project 多人共享：MVP 單人視角是否足夠？共享邀請 / 權限模型待定 | 先驗證單人價值，再設計協作 |
| Q2 | 學期定義（起訖、考試週）由使用者設定還是學校匯入？ | MVP 手動設定 |
| Q3 | 技術棧定案（見 implementation plan 建議） | 待確認 |
